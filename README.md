## How I work with AI

<a href="https://rodrigogs.github.io/#ai"><img alt="How I work with AI: Spec before code, A team, not a chatbot, Adversarial review, Proof, not &quot;looks right&quot;, Research over memory, Memory across sessions, Guardrails, An agent on call." src="https://rodrigogs.github.io/readme/method.svg" width="100%"></a>

<details><summary>The method as text</summary>

1. **Spec before code**: Big changes start as a written spec and a plan before any code; bugs start from the symptom, and finding the cause is the agents' job.
2. **A team, not a chatbot**: Work fans out to parallel subagents, each with its model and effort picked for the job: fast models for mechanical edits, the strongest for architecture and review.
3. **Adversarial review**: Independent reviewer agents try to refute every finding and audit truth, accessibility and performance before I accept a change.
4. **Proof, not "looks right"**: Done means verified: agents drive the running app in a real browser, check the deployed URL and watch CI before anything is called finished.
5. **Research over memory**: Before a decision, agents read current docs and search the web instead of trusting what a model remembers.
6. **Memory across sessions**: A persistent memory layer keeps long projects coherent across days and sessions.
7. **Guardrails**: Nothing other people can see (pull requests, comments, posts) goes out without my approval, and secrets stay out of every output.
8. **An agent on call**: A self-hosted agent I can reach from my phone over Telegram picks up work when I am away from the desk.

This site and my GitHub profile were built this way: planned, built by parallel agents, reviewed adversarially and verified live.
